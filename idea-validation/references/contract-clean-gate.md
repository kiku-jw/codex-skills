# Contract-Clean Gate

Use this gate before spending more time on an idea that might be adjacent to past client work, moderation work, sensitive data, or ambiguous rights.

## Hard Reject Conditions

Reject the idea immediately if the wedge depends on any of these:

- contract-bound data, logs, labels, screenshots, or internal exports
- derived patterns, rules, or work product created during restricted client work
- account sharing, third-party delegation, or hidden operator substitution
- prohibited tooling, including tools the contract explicitly or implicitly blocks
- gray scraping, ToS evasion, or sensitive data without a clean right to process it

## Yellow Flags

Treat the idea as risky and require a cleaner reshape if it:

- sits in the same domain as old restricted work but uses new data
- could be mistaken for reusing a former client's internal methods or assets
- depends on private context that cannot be shown safely in a demo or landing page
- needs a justification like "the contract probably does not mean this literally"

## Green Starting Surfaces

Prefer ideas built on:

- the builder's own data and personal archives
- manual uploads explicitly controlled by the user
- public official APIs, changelogs, docs, exports, and feeds
- newly collected clean datasets with explicit rights

## Example Parked Adjacencies

These stay parked unless the rights surface changes materially:

- moderation data or anything derived from it
- wedges that rely on contract-era data, patterns, or work product
- tools that help someone else operate a restricted third-party account
- helper clients or automation layers for restricted moderation work

## Pass Criteria

An idea passes the gate only if all of these are true:

- the data surface is clean
- the rights surface is clean
- the operator model is clean
- the value can be demonstrated without leaking restricted context
- commercial upside does not depend on contract-gray behavior
